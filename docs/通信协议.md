# 通信协议

单片机通过 ESP8266 以 **TCP 客户端**身份连接服务器，定时上报一帧状态；服务器可下发短指令修改阈值。协议是自定义的定长 ASCII 帧，没有包长度字段，靠固定长度切分。

## 1. 连接流程（AT 指令）

```c
AT+CWJAP="SSID","PASSWORD"          // 连路由器
AT+CIPSTART="TCP","0.0.0.0",0000    // 连服务器（地址与端口换成自己的）
AT+CIPSEND=17                       // 声明本次发送 17 字节
<17 字节数据>
```

> 注意：`AT+CIPSEND=n` 里的 n 必须与随后实际发送的字节数一致，否则模块会等到超时，表现为「数据时有时无」。原例程写的 20 与实际帧长 17 不一致，已修正。

## 2. 上行帧格式（17 字节，全部为 ASCII 可见字符）

| 偏移 | 长度 | 含义 | 取值 | 示例 |
|---|---|---|---|---|
| 0~2 | 3 | 帧头 | 固定 `123` | `123` |
| 3~7 | 5 | 温度 | `xx.x` 格式，整数部分不足 3 位高位补空格，单位 ℃ | ` 33.5` |
| 8~9 | 2 | 烟雾实时值 | `00`~`99`，由 ADC0832 采值换算 | `07` |
| 10 | 1 | 烟雾报警状态 | `0`=正在报警，`1`=正常 | `1` |
| 11 | 1 | 温度报警状态 | `0`=正在报警，`1`=正常 | `1` |
| 12 | 1 | 手动报警状态 | `0`=手动报警中，`1`=正常 | `1` |
| 13~14 | 2 | 烟雾报警阈值 | `00`~`99` | `04` |
| 15~16 | 2 | 温度报警阈值 | 整数部分，单位 ℃ | `33` |

完整示例（33.5℃、烟雾 07、无报警、烟雾阈值 04、温度阈值 33）：

```
123 33.50711140 33
```

去掉空格后即 `123 33.5` + `07` + `111` + `04` + `33` = 17 个字符。

### 为什么状态位用 `0` 表示报警

这是原例程的约定：`0` 表示「该路处于报警中」，`1` 表示正常。写代码时容易反，调试时先在串口助手里把四种组合都造出来对一遍，比改完直接烧板子快。

## 3. 下行指令

服务器向单片机发送 2 字节指令，格式 `B` + 数字：

| 指令 | 作用 | 实现 |
|---|---|---|
| `B1` | 温度阈值 +1.0℃ | `s_temp += 10`（单位 0.1℃，上限 160） |
| `B2` | 温度阈值 −1.0℃ | `s_temp -= 10` |
| `B3` | 烟雾阈值 +1 | `s_dengji++`（上限 99） |
| `B4` | 烟雾阈值 −1 | `s_dengji--` |
| `B5` | 切换手动报警 | `shoudong = ~shoudong` |

单片机收到后立即写 EEPROM，掉电不丢；同时下一帧上报里就能看到新阈值。

## 4. 已知问题与改进方向

| 问题 | 影响 | 改法 |
|---|---|---|
| 无帧头校验/无长度字段 | 串口误码会导致整帧错位 | 加 `0xAA 0x55` 帧头 + 累加和校验 |
| 明文 TCP，无鉴权 | 任何人知道 IP 就能伪造上报 | 加设备密钥或换 MQTT + token |
| 断线不重连 | WiFi 掉线后一直静默 | 定时发 `AT+CIPSTATUS` 判断，掉线重发 CIPSTART |
| 无本地缓存 | 断网期间数据丢失 | 环形缓冲区存最近 N 帧，恢复后补传 |

这几条是这套方案从「课程作业」走向「能交付现场」的差距，也是后续想补的部分。
